Day 1 review

The habit: Mask → Ask → Check

The one habit from Day 1. Use these three steps every time you use Copilot for work, and when you build an agent.

1 · Mask

Before you paste anything, remove or replace sensitive data. Pricing, CUI, and health information never go in.

2 · Ask

Write the prompt with Goal, Context, Source, and Expectations.

3 · Check

Read the output as if you will sign it, because you will.

Ask: the four parts of a good prompt

PartAnswers the questionExample
GoalWhat do I want?Write a status update on the Building B-214 cooling problem.
ContextWhy, and for whom?It's for the COR, who wants to know whether classes will be disrupted next week.
SourceWhat should it use?Use only the technician notes below.
ExpectationsWhat should the result look like?Under 150 words, three short paragraphs: what happened, what we're doing, what's next.

Follow-up moves

  • Shorten: "Cut this to half the length. Keep the dates."
  • Re-aim: "Rewrite this for the technicians instead of the COR."
  • Reshape: "Put this in a table with columns Date, Problem, Action, Result."
  • Challenge: "What's missing or unclear? What would a skeptical reader ask?"
  • Show your work: "Which parts of your answer came from my notes, and which did you add?"

Check: before you use any output

  • Every fact, number, date, and name matches the source.
  • Nothing was added that I didn't provide, such as response times, phone numbers, or job titles.
  • It follows TIYA policy and doesn't commit TIYA to anything I can't commit to.
  • The tone fits the reader.
  • I put back any masked details, outside of Copilot.
  • I would sign my name to it.

Agent foundations

It's been a few months since Day 1. "The habit" at the front of this workbook is your one-page review; the full Day 1 workbook is on the course page. Mask → Ask → Check applies to agents too, with one addition: an agent's knowledge has to be safe for everyone the agent is shared with.

Day 2 · 10:30 – 12:15

Building real agents

An agent's instructions are a prompt that never ends. Write your tests first: questions whose right answers you already know.

Instructions template

You are [name], [one-sentence purpose].
Audience: [who uses it and what they need].
Knowledge: Use only [sources]. If the answer isn't there, say so and [who to ask].
Steps: 1. [ ] 2. [ ] 3. [ ]
Output: [format, length]. Always end with [source citation, next step, etc.].
Boundaries: Never [ ]. If asked about [ ], [hand off to a person].
Tone: [ ].
Build 140 min

SOP Navigator

ArchitectureKnowledge Q&A

  1. In Copilot Chat, choose to create an agent and switch to the configure view.
  2. Name: TIYA · FM · SOP Navigator
  3. Description: Answers questions about TIYA facilities SOPs, with the SOP and section for each answer. Doesn't answer from general knowledge.
  4. Instructions: paste the block below.
  5. Knowledge: add the AI Training Sandbox SOP folder (four SOPs).
  6. Starter prompts: "What counts as an emergency work order?" · "Who approves overtime?" · "How often do rooftop units get PM?"
  7. Run the five tests in the preview. Fix the instructions for any failure and rerun.
Instructions
You are the SOP Navigator for TIYA Services facilities staff. You answer questions about standard operating procedures using only the SOP documents in your knowledge.

Audience: technicians, leads, and admin staff who need a quick, accurate answer while working.

How to answer:
1. Find the SOP and section that answers the question.
2. Answer in plain language in 5 sentences or fewer, or as numbered steps if the question is about a procedure.
3. End every answer with the source, formatted as: Source: [SOP number], [title], section [number].

Boundaries:
- If the answer is not in the SOPs, say "I can't find that in the SOPs" and suggest asking a supervisor. Don't answer from general knowledge.
- If someone describes an emergency happening now, first tell them to call the Emergency Work Order Desk as described in FM-SOP-07, then answer.
- Never ask for or repeat names, phone numbers of individuals, health information, pricing, or contract numbers.
- If two SOPs seem to conflict, show both and say a supervisor needs to decide.

Tone: direct and helpful. Use the SOPs' own terms.

Test plan

#Test questionRight answerPass?Fix
1What's the completion target for an Urgent work order?3 calendar days; respond within 1 business day (FM-SOP-03 §4)
2Who has to be told about an after-hours emergency, and when?COR: email same night, phone at 0700. FM Manager: by 0800 next business day (FM-SOP-07 §3, §5)
3How much overtime can I work without approval?None, except during an Emergency response; supervisor approves next business day (ADM-SOP-02 §3)

Work Order Analyst

ArchitectureMulti-tool: knowledge + code interpreter + uploaded file

  1. Create a new agent. Name: TIYA · FM · Work Order Analyst
  2. Knowledge: add only FM-SOP-03 Work Order Priority Definitions.
  3. Capabilities: turn on code interpreter.
  4. Instructions: paste the block below.
  5. In the preview, upload work-orders-aug-sep-2026.csv and type "Analyze this export."
  6. Check three numbers yourself by opening the CSV in Excel.
Instructions
You are the Work Order Analyst for TIYA Services facilities leads. When a user uploads a work order export (CSV or Excel), analyze it with code and report:

1. Scope: the number of rows and the date range you analyzed, so the user can confirm you read the whole file.
2. Totals: open vs. closed, broken down by priority and by building.
3. Overdue: open work orders past the completion target for their priority in FM-SOP-03, measured from the latest date in the file. List them in a table.
4. Repeat failures: following FM-SOP-03 section 5, look for 3 or more work orders on the same equipment within 60 days. Exclude Scheduled (preventive maintenance) work orders. Read the descriptions; don't rely on counts alone.
5. A bar chart of open work orders by priority.
6. A 3-sentence summary a lead could paste into a weekly report, labeled DRAFT.

Always show the filters and calculations you used. If a value doesn't match FM-SOP-03's priorities, list those rows instead of guessing.
Never recommend staffing, discipline, or spending decisions; say those need a supervisor's judgment.

Check it: How many rows? ____  Open work orders? ____  Which equipment is a repeat failure? ____________

Publishing checklist

  • Name follows TIYA · [Team] · [Job].
  • Description says what it does, what it doesn't do, and who owns it.
  • Every person I share with can already open every knowledge source. (Sharing the agent doesn't share its sources.)
  • Nothing in the knowledge is red, and nothing amber is unmasked.
  • All five tests pass, including the refusal tests.
  • Shared with named people only. Wider sharing goes through TIYA's review.
  • Starter prompts show people what to ask.

Day 2 · 3:15 – 4:30

Governance and security

An instruction is a request. Permissions are a lock. If the agent can't read it, it can't leak it.

Never put these in an agent's knowledge

  • HR and personnel files, performance records
  • Medical, injury, or workers' comp records
  • Pricing, cost data, bids, proposals, vendor quotes
  • CUI
  • Security details: access codes, alarm and camera information
  • Any folder whose permissions you haven't checked
